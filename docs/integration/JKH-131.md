### Recoil-coverage clarification — frozen before review repair

The `FIREARMS[*].recoil.{spreadKick,maxPenalty}` registry pair is a frozen
**project presentation** value used by `app/page.tsx` viewmodel recoil. It is
tested as such, separately from the ballistic punch oracle. It is not a
ReGameDLL KickBack tuple and does not establish the actual shot recoil below.

The actual ballistic oracle uses the source-labelled KickBack tuples recorded
in `CS16_REFERENCE.md`, with pitch/yaw in **degrees**. For deterministic module
testing, seed `131` gives the following first and second punch totals; returned
`shot().kick` is the same per-shot delta converted to radians. The expected
branch selection uses 4 scene units/s (160 source units/s) for `run`, 0 speed
for `air`, `crouch`, and `stand`.

| AK air | 2, 1 | 5, 2.7 | 9, 6 |
| AK crouch | .9, .35 | 2.1, .75 | 5.5, 1.5 |
| AK stand | 1, .375 | 2.35, .825 | 5.75, 1.75 |

For the cap control, project seed `476` must keep the direction positive for
the first 30 calls; every automatic branch reaches the listed positive pitch
and yaw cap without exceeding it. Seed `131` flips direction only after the
second AK-air shot among the twelve cases; the other eleven retain direction
positive at that point. This checks the project RNG implementation
deterministically; it does not claim original-engine RNG equivalence.

The six pistols and AWP use the pinned default first-shot punch of 2° pitch and
0° yaw. M3 uses the seeded project random ground/air first punches of 4° and 9°
pitch respectively with seed `131`, again with 0° yaw. These are isolated
ballistic-state checks, not a player-runtime recoil receipt.

The initial repair-control run exposed a card arithmetic error in the two AK
second-shot yaw totals: the source formula adds `2 * lateralModifier`, producing
`.75` for crouch and `.825` for stand. The failed control is retained as
`outputs/jkh-131/review-repair-issue-test.log`. This corrects the independent
oracle calculation only; it changes no source reference, threshold, module, or
claimed runtime behavior.

Damage traces use direct target distances `0`, `12.5`, and `25` scene units
(0, 500, and 1000 source units), plus each weapon's exact maximum range and one
source-unit beyond it. Non-M3 direct damage must equal
`floor(baseDamage * rangeModifier^(sourceDistance / 500)) * hitGroupMultiplier`;
M3 uses `floor(20 * (1 - sourceDistance / 3000)) * hitGroupMultiplier` for each
pellet. Hit-group multipliers are head 4, torso 1, stomach 1.25, leg 0.75.
Armor traces cover no armor, armor without helmet, and armor with helmet; their
oracle is the production `applyArmorDamage` transformation and verifies that
`resolveBulletDamage` preserves health, armor, and helmet state without a
second scalar.

Penetration traces use the frozen project constants in
`weapon-penetration.ts`: one direct hit for all eleven firearms; count-one
weapons reject a wall exit; rifle/carbine/Deagle permit one qualifying exit;
AWP permits two; malformed exits, repeat colliders, over-thickness, depleted
power, and exhausted remaining range reject. Material pairs are metal `[.15,
.2]`, concrete `[.25, null]`, wood `[1, .6]`, grate `[.5, .4]`, vent `[.5,
.45]`, tile `[.65, .3]`, computer `[.4, .45]`, and default `[1, null]`. These
are an explicitly labelled reconstructed/project penetration approximation,
including finite AABB exits, not original collision equivalence.

Special-state traces require no state leaks: Glock cancellation on empty ammo,
reload, switch, death, reset, and explicit cancellation; USP/M4 interruption
reverts an unfinished attachment while completed attachments persist; AWP
cycles unscoped/40-FOV/10-FOV/unscoped, unzooms after a scoped committed shot,
and restores the saved stage at 1450 ms unless canceled; M3 transfers reserve
only at insert deadlines and remains interruptible after one loaded shell.
